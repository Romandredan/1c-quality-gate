# Гейт качества: перегрузка контекста и маршрутизация знания

Разбор по состоянию репозитория на v3.5.0 (7 сентября 2026) и по 25 реальным отчётам гейта в
проекте пользователя (9 августа — 6 сентября).

## 1. Замер: что модель читает до первой строки кода

Горячий путь — файлы, которые навыки предписывают прочитать при прогоне соответствующего
класса. Считались только обязательные чтения, без вывода инструментов и без самого кода.

| Класс | Байт | ≈ токенов | Комментарий |
|---|---|---|---|
| C0 | 73 КБ | 27k | оркестратор + формат следа + гигиена + контракт маршрутизации |
| C1, контур кода L1 | 249 КБ | 95k | из них **131 КБ — два справочника с пометкой «прогоняется всегда»** |
| C1 + архетип `query` | 289 КБ | 107k | плюс два справочника по запросам |
| C2 + архитектура | 363 КБ | 138k | плюс навык, карта признаков, чеклист, антипаттерны архитектуры |

Для сравнения: сам изменённый код в типичном прогоне C1 — одна-две тысячи строк, то есть
10–20k токенов. Инструкции превосходят предмет проверки в 5–10 раз.

Динамика: бюджеты навыков подняты трижды за три недели (оркестратор 28→29 КБ, контур кода
25→26→27 КБ). В комментарии к бюджету записано, что свободного места оставалось 47 байт.
Каждый новый признак добавляет строку в таблицу навыка, раздел в справочник, пункт в
чеклист, упоминание в агенте и запись в тест. Навык растёт линейно от числа правил — это
неправильная форма роста: он должен расти от числа *видов шагов*, а правила — жить в данных.

## 2. Что «всегда читаемые» 131 КБ дают на выходе

По 25 отчётам с секцией `## quality evidence`:

| Источник находок | Записей следа `applied` | Находок в человекочитаемой части |
|---|---|---|
| `static-analysis` (инструмент) | 269 | много, с триажем |
| прочие инструменты (`query-lint`, `bsl-lint`, валидаторы XML) | ~150 | есть |
| `ai-antipatterns.md` (22 признака `qg:AI-NN`, 85 КБ) | **0** — для него нет `scope` | **0** (одно упоминание AI-07 без severity) |
| `bsl-anti-patterns.md`, немеханизированная часть (10 антипаттернов, 49 КБ) | 3 (`query-in-loop`) | **0** с формулировкой «антипаттерн «…»» |

Два прочтения: либо код чист от этих антипаттернов, либо проход по 131 КБ выродился в ритуал.
**Различить их невозможно по конструкции**: в закрытом словаре `evidence-scopes.mjs` у
контура кода пять модельных проверок — `query-in-loop`, `api-verification`, `naming-std454`,
`query-execution`, `adversarial-audit`. Прохода по AI-антипаттернам и по большей части
платформенных антипаттернов среди них нет. Модель не может написать ни `applied`, ни
`skipped` — а инвариант №5 оркестратора говорит, что молчание неотличимо от выполнения.

Это не «много текста», а структурная дыра: самые дорогие по контексту проверки —
единственные, которые не оставляют следа. Плагин нарушает собственный первый принцип
ровно в том месте, где платит за это больше всего.

Второй симптом того же рода: агент `bsl-verifier` (haiku, механический чеклист) в п. 6
инструктирован проверять по `ai-antipatterns.md`. Семантический свод на 85 КБ загружается в
дешёвую модель, чей профиль — сигнатуры и существование методов. По собственной таблице
маршрутизации моделей это ошибка адресации.

## 3. Почему не помогает «просто вынести в дочерние файлы»

Вынос в `references/` уже делался дважды (15 и 31 августа) и работает там, где вынесено
обосновывающее: `profile-axes`, `run-environment`, `cold-reader` читаются только по нужде.
Но три вещи он не решает:

1. **Пометка «всегда».** Файл в `references/` с инструкцией «прогоняется всегда, при любой
   глубине» — те же токены, только через дополнительный вызов Read. Маршрутизация по файлам
   без маршрутизации по *моменту чтения* ничего не экономит.
2. **Смесь детекции и разбора.** Каждая карточка антипаттерна: «Что искать» (2–4 строки) +
   «Почему опасно», «Как правильно», «Законные формы» (30–60 строк). Для обнаружения нужны
   только триггеры; разбор нужен только при попадании. Сейчас грузится всё, соотношение
   примерно 1:15.
3. **Таблицы в навыке дублируют машинные реестры.** Таблица инструментов в оркестраторе и
   таблица признаков в контуре кода повторяют то, что знают `evidence-scopes.mjs` и
   `bsl-lint.mjs`. Тест-бюджет прямо пишет: «имя оттуда не вынести — по этой таблице
   оркестратор узнаёт, что строку печатает инструмент». Верно, пока это узнаёт из прозы. Если
   план прогона печатает инструмент — таблица в навыке не нужна.

## 4. Предлагаемая маршрутизация: по исполнителю и моменту, а не только по файлам

Четыре яруса. Каждый отвечает на вопрос «кто это читает и когда».

### Ярус 0 — навык оркестратора: инварианты и цикл

Инварианты (уже выделены) и цикл «план → прогон → сбор → отчёт → снятие», где каждый шаг —
команда. Никаких таблиц правил и инструментов. Целевой размер — до 12 КБ против 29.

### Ярус 1 — план прогона печатает инструмент

`gate.mjs plan` (или расширение `status`) по списку изменённых файлов печатает:

- профиль: класс, сработавшие архетипы, драйвер, готовую строку `scope` со `config=`;
- команды инструментов для этого состава файлов, в порядке выполнения;
- модельные проходы с указанием, **какие карточки правил загрузить**;
- субагентов, которых нужно запустить, с готовыми вопросами.

Это заменяет матрицу глубин, таблицу инструментов, таблицу «архетип → справочники» и
таблицу признаков. Объём считается из diff, архетипы — регулярными выражениями по маркерам
(они уже перечислены в таблице), сложность — из отчёта `analyzer-run.mjs --json`, который
навык и так велит использовать. Модель вправе поднять глубину с записанной причиной, но
базовый профиль перестаёт быть пересказом по памяти и становится проверяемым. Побочный
выигрыш — исчезает класс ошибок «метка `queries` вместо `query`», которую валидатор сейчас
ловит постфактум.

### Ярус 2 — карточки правил: триггер отдельно от разбора

- `catalog/<id>.md` — одна карточка на признак (`qg:AI-NN`, `qg:BSL-*`, антипаттерны
  производительности), фиксированные секции: Триггер / Почему / Как чинить / Законные формы /
  Чем механизирован.
- `catalog/index.md` — **генерируется** из карточек (по образцу `gen-signs-map-md.mjs`):
  только идентификатор, severity и строка-триггер. Порядка 40 признаков по две строки —
  6–8 КБ. Это единственное, что загружается на проход обнаружения.
- Полная карточка читается в двух случаях: кандидат найден и нужен разбор с контр-сигналом,
  либо инструмент вернул этот признак и нужно «как чинить».
- Пакеты архетипов (какие карточки и какие справочники стандартов активирует `query`,
  `form-module`, `transaction`) — данные в реестре, не проза.

Контур архитектуры уже устроен так: `signs-map.json` как источник истины, поле `requires`
вместо перечня в тексте, генерируемый `signs-map.md`. Нужно довести этот образец до контура
кода.

### Ярус 3 — модельный проход по антипаттернам в изолированном агенте

Проход по каталогу — интерпретация с фиксированным сводом. Это кандидат на отдельного
агента-читателя уровня не ниже sonnet (haiku здесь неуместен по той же причине, что и в
верификаторе). Вход: индекс триггеров, содержимое изменённых файлов, сравнение версий.
Выход: список кандидатов с идентификаторами карточек и строками. Второй такт (тот же агент
или оркестратор) загружает полные карточки только по кандидатам и выносит вердикт с
контр-сигналом.

Что это даёт:

- 131 КБ уходят из контекста оркестратора, где они конкурируют с историей диалога, diff и
  выводом инструментов;
- читатель не знает формулировки задачи — то самое условие «холодного читателя», которое
  навык уже обосновал для Слоя 2;
- появляется запись следа `applied: scope=ai-antipatterns, ids=[…]` и парная для
  платформенных антипаттернов — новые `scope` в словаре, обязательные при L1 контура кода.
  Валидатор отклоняет отчёт без них так же, как сейчас отклоняет отчёт без
  `not_verified: compilation`.

Агент `bsl-verifier` при этом перестаёт грузить `ai-antipatterns.md` вовсе.

### Ярус 4 — обосновывающее остаётся где лежит

`profile-axes`, `run-environment`, `cold-reader`, `glossary`, `adversarial-audit` — читаются
по ссылке из навыка по нужде. Здесь менять нечего.

## 5. Что придётся переделать в тестах

Тест «правило на месте» (~110 пар файл → строка) и тест достижимости справочников привязаны
к путям и к тексту навыка. При переходе к каталогу:

- достижимость проверяется от реестра и от вывода `gate.mjs plan`, а не от упоминания в
  SKILL.md: правило применяется, если план его называет;
- пары «правило на месте» переезжают на карточки; часть из них станет структурной проверкой
  «у каждой карточки заполнены все пять секций» — это сильнее точечных строк;
- бюджеты навыков снижаются, а не поднимаются: у оркестратора до 12 КБ, у контура кода до
  14 КБ. Число в бюджете снова становится долгом, названным вслух, только со знаком минус.

## 6. Как понять, была ли деградация на самом деле

Каждая карточка `qg:AI-NN` получена «из реальной переработки сгенерированного кода». Эти
случаи лежат в истории проекта пользователя. Из них собирается набор регрессионных фикстур: diff до
переработки и ожидаемый идентификатор. Прогон читателя (ярус 3) по фикстурам даёт полноту
обнаружения, которую можно сравнить до и после перестройки. Без этого набора вопрос «код чист
или проход слеп» останется без ответа при любой архитектуре.

## 7. Порядок работ

Каждый шаг ценен сам по себе и не требует следующего.

1. **Словарь.** Добавить `scope` для двух модельных проходов и требовать `applied`/`skipped`
   при L1 контура кода. День работы, дыра становится видимой немедленно.
2. **Карточки и индекс.** Разрезать два больших справочника, сгенерировать индекс триггеров,
   заменить «прогоняется всегда» на «загрузи индекс; карточку — по попаданию». Горячий путь C1
   сокращается вдвое.
3. **Агент-читатель.** Проход по каталогу в изолированного агента уровня sonnet;
   верификатор освобождается от семантического свода.
4. **План прогона инструментом.** `gate.mjs plan` с профилем и командами; таблицы из навыков
   уходят в реестр; тесты достижимости переписываются от реестра.
5. **Фикстуры из истории.** Набор регрессии по происхождению карточек и замер полноты до и
   после.

## 8. Чего делать не стоит

- Дробить файлы дальше, сохранив пометку «всегда»: те же токены, больше вызовов Read.
- Переносить таблицы правил в справочники, оставив тест «навык обязан назвать правило» в
  прежнем виде: он вернёт таблицы обратно при первом же новом признаке.
- Отдавать семантические антипаттерны haiku ради экономии: по собственной таблице
  маршрутизации моделей это интерпретация, а не механика.
- Считать перестройку завершённой без замера полноты по фикстурам: иначе экономия контекста
  доказана, а сохранность обнаружения — нет.
