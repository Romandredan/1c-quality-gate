## Триггер

Сравнение двух дат (`=`, `<>`, `>`, `<`) там, где смысл — календарный день, а в значении может
быть время: дата документа, дата события, день, выбранный пользователем.

## Почему

Дата в языке — момент времени. `Дата(2026, 11, 10)` — это 00:00:00, а значение, прочитанное из
документа или пришедшее от внешней стороны, обычно содержит время операции. Равенство
`Дата = &Дата` при этом ложно, и проверка «дата не менялась» пропускает изменение; обратное
сравнение `<>` срабатывает на той же самой дате. По тексту дефекта не видно: сравнение
выглядит симметричным, а на данных с нулевым временем ведёт себя правильно — поэтому прогон на
подготовленных записях его не показывает.

## Как чинить

Сравнивать начало дня с обеих сторон: `НачалоДня(Одна) = НачалоДня(Другая)`. Для диапазона —
нижняя граница `НачалоДня(День)`, верхняя `НачалоДня(ДобавитьКДате(День, 1, "День"))`.

#### Неправильно

```bsl
Если Параметры.Дата = Исходник.ДатаЧека Тогда
	Проверка.Пройдено = Ложь; // та же дата со временем сюда не попадёт
КонецЕсли;
```

#### Правильно

```bsl
Если НачалоДня(Параметры.Дата) = НачалоДня(Исходник.ДатаЧека) Тогда
	Проверка.Пройдено = Ложь;
КонецЕсли;
```

## Когда это не дефект

- сравниваются моменты, и время — часть смысла: метка события, время постановки в очередь;
- обе стороны уже приведены к началу дня до сравнения;
- точность ограничена часом или минутой, и это оговорено в постановке.

## Что проверяет инструмент

Ничего: тождество «здесь имеется в виду день, а не момент» из текста не выводится — его
устанавливает читатель по предмету поля. В текстах запросов тот же класс дефекта (границы
периода без учёта времени) тоже остаётся на чтении.
