## Триггер

Строка документа заполняется суммой налога и суммой с налогом, а реквизит документа «цена
включает налог» в этой ветке не прочитан или прочитан только в одной из двух сумм.

## Почему

База налога зависит от режима: при включённом налоге он выделяется из суммы, при выключенном —
начисляется сверху. Ветка, написанная под один режим, даёт расхождение в ставку на каждой
строке, но документ при этом проводится: сумма строки равна цене, итог сходится сам с собой,
не сходится только налог. Ни сборка, ни сверка итогов документа ошибку не показывают —
расхождение видно лишь в сравнении с ожидаемой суммой налога.

## Как чинить

Читать признак документа и считать обе суммы по одной ветке. Базу брать из данных основания,
а не из восстановленного приближения: доля налога в цене и налог, начисленный на цену, — разные
формулы.

#### Неправильно

```bsl
Строка.Цена = Сумма;
Строка.Сумма = Сумма;
Строка.СуммаНДС = Окр(Сумма * Ставка / 100, 2);
Строка.СуммаСНДС = Сумма + Строка.СуммаНДС;
```

#### Правильно

```bsl
Строка.Цена = Сумма;
Строка.Сумма = Сумма;
Строка.СуммаНДС = ?(Документ.ЦенаВключаетНДС,
	Окр(Сумма * Ставка / (100 + Ставка), 2),
	Окр(Сумма * Ставка / 100, 2));
Строка.СуммаСНДС = ?(Документ.ЦенаВключаетНДС, Сумма, Сумма + Строка.СуммаНДС);
```

## Когда это не дефект

- режим зафиксирован контрактом обмена: все строки приходят с ценой без налога по правилу;
- сумма налога берётся из основания, а не рассчитывается;
- расчёт предварительный — для экрана или отбора, и по нему документ не проводится.

## Что проверяет инструмент

Ничего: нужно знать, что означает признак и как устроен контракт документа. Арифметическая
сверка «налог = база × ставка» проходит в обоих режимах по отдельности — ошибку показывает
только сравнение двух режимов на одной строке.
