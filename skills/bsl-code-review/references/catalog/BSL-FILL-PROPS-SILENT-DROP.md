## Триггер

`ЗаполнитьЗначенияСвойств` переносит значения в приёмник, состав которого задан не здесь:
структуру создали с одним-двумя ключами, а список имён шире, либо имена приходят списком.

## Почему

Метод переносит только те свойства, которые у приёмника уже есть; отсутствующие молча
пропускает и новых не создаёт. Ни вызова, ни сборки это не ломает: строка читается как
«перенести значения», а фактически переносится подмножество. Проверка, написанная на перенос,
подтверждает успех — она смотрит на код возврата или на отсутствие исключения, а не на поля
приёмника. Данные теряются на том поле, ради которого перенос и делался.

## Как чинить

Структуру строить с полным составом ключей до вызова либо заполнять явными `Вставить` по
каждому ключу. Переносить в объект, состав свойств которого задан метаданными, тоже можно —
там промах имени ловится на разработке, а не в проде.

#### Неправильно

```bsl
Результат = Новый Структура("Ошибка");
ЗаполнитьЗначенияСвойств(Результат, Разбор); // в Разбор есть Вердикт, Марка, Код
Возврат Результат; // Вердикт не перенесён: ключа в приёмнике не было
```

#### Правильно

```bsl
Результат = Новый Структура;
Результат.Вставить("Ошибка", Разбор.Ошибка);
Результат.Вставить("Вердикт", Разбор.Вердикт);
Результат.Вставить("Марка", Разбор.Марка);
Возврат Результат;
```

## Когда это не дефект

- список имён построен из состава приёмника обходом его свойств;
- приёмник — ссылка или объект, и состав полей задан метаданными;
- перенос подмножества и есть цель: лишние имена перечислены намеренно и оговорены.

## Что проверяет инструмент

Ничего: чтобы понять, есть ли имя в приёмнике, нужно знать состав структуры, а он вычисляется
в рантайме. Вопрос «откуда пришла структура» задаёт соседний признак
`qg:BSL-OWN-STRUCTURE-CHECK`; молча потерянное поле ловится проверкой результата на уровне
метода, а не текста.
