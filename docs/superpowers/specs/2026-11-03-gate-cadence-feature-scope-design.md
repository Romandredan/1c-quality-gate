# Ритм гейта: один прогон на фичу, а не по правке

**Дата:** 2026-11-03 · **Статус:** принято, реализовано

## Зачем

Живая сессия OpenCode (TradeProd, 03.11.2026) показала 17 прогонов гейта за день: модель
снимала гейт после каждого пакета правок, и блокирующее сообщение плагина на каждой паузе
сессии запускало новый цикл. Решение владельца: гейт проверяет **фичу целиком в рамках
сессии** — детерминированные точечные прогоны по правке не показательны для ревью, а
per-этапный ритм прерывает работу.

## Диагноз (факты)

1. Взвод гейта на каждую правку — штатная механика (`armAfterEdit`), аналог PostToolUse
   Claude Code; он не является проблемой и не меняется.
2. В OpenCode нет жёсткого Stop-хука: плагин работает через `session.idle` /
   `session.execution.succeeded`, и любая пауза читается как попытка завершения. Это
   ограничение харнесса, механику гейта оставляем как есть (лимит 3 возврата на неизменный
   состав правок).
3. Per-этапный ритм создавался текстами: подсказка при взводе печатала «Проверка после этой
   правки станет проходом N из M», а режим opencode угрожал «плагин будет возвращать тебя
   к работе на каждой паузе» — модель читала это как приказ прогонять и снимать гейт после
   каждого этапа, чтобы не прерываться.

## Подходы

- **A. Только тексты (выбран).** Убрать сигнал per-правочного ритма из подсказки при взводе;
  в блокирующем сообщении на паузе явно разрешить продолжать работу, если задача не окончена.
  Механика не тронута, риск минимальный; эффект — текстовое руководство модели.
- **B. Механика гашения возвратов** (один возврат на сессию, кулдаун). Отклонено: окончание
  задачи в OpenCode неотличимо от промежуточной паузы, любая эвристика ослабляет несущую
  функцию гейта — не оставить непроверенное.
- **C. Ритм в конфиге** (`cadence: feature|edit`). Отклонено: второй режим противоречит
  принятому решению; переключатель ради отвергнутого режима не нужен.

## Что изменено

- `hooks/gate-core.mjs`, `gateHint`: убрана строка «Проверка после этой правки станет
  проходом N из M» (параметр `passes` в сигнатуре сохранён для совместимости вызовов);
  добавлен явный ритм: «Проверка — одна на всю работу, а не после каждой правки…»;
  хвост opencode переписан с угрозы («будет возвращать на каждой паузе») на нейтральное
  «напомнит на паузе — продолжай работу, если задача не окончена».
- `hooks/gate-core.mjs`, `blockMessage`: добавлено «Если задача не окончена — это
  промежуточная пауза: продолжай работу, гейт останется взведённым…» (оба режима).
- `skills/quality-gate/SKILL.md`: описание — «один прогон на всю правку фичи, а не после
  каждого отдельного изменения файла или промежуточного этапа».
- `tests/gate-core.test.mjs`: проверка «подсказка называет следующий проход» заменена на
  инверсию + новые проверки ритма; проверка честности про мягкий гейт — на новую формулировку.

Номер прохода и потолок по-прежнему называются **в момент блокировки** (handoffLines,
blockMessage при `passes > 0`) — там это относится к циклу исправлений одного прогона,
а не к ритму правок.
