## Триггер

Три и больше `Приемник.Х = Источник.Х` из одного источника в один приёмник.

## Почему

Строку выборки перекладывают в структуру параметров, реквизиты учётной записи — в структуру
настроек, параметры — в менеджер записи, и каждый раз поле за полем. Каждая такая строка —
второе описание состава данных. Поле, добавленное в источник, до приёмника не доедет, и
сообщения об этом не будет: перенос просто не знает о новом поле.

Разноимённый перенос (`Параметры.ВнешнийСервис = Строка.Протокол`) хуже одноимённого: одно
значение ходит по коду под двумя именами, и каждый следующий читатель сверяет их заново.

## Как чинить

#### Неправильно

```bsl
Параметры = ПараметрыПостановки();
Параметры.Идентификатор = Строка.Идентификатор;
Параметры.Основание     = Строка.Основание;
Параметры.Склад         = Строка.Склад;
Параметры.Операция      = Строка.Направление;
ПоставитьВОчередь(Параметры);
```

#### Правильно

```bsl
// В запросе поле названо именем приёмника: «... КАК Операция»
ПоставитьВОчередь(Строка);
```

Строка таблицы значений читается по имени поля так же, как структура, поэтому метод,
принимающий параметры по имени, работает с ней без промежуточной структуры. Когда вторая
структура всё-таки нужна — `ЗаполнитьЗначенияСвойств(Приемник, Источник)`, при необходимости
со списком свойств строкой. Разноимённое поле переименовывается у источника: у строки выборки
это псевдоним поля в тексте запроса.

## Когда это не дефект

- при переносе значение преобразуется (`СокрЛП`, `Число`, выражение) — такую строку
  `ЗаполнитьЗначенияСвойств` не заменит; если без неё порог не набирается, инструмент задаёт
  вопрос, а не утверждает дефект;
- у значения два адресата с разными словарями полей — например, отчёт оператору, где поле
  названо по предметной области, и регистр очереди со своим именем. Перенос в одного из них
  законен и поясняется комментарием над ним со словом «словарь»;
- одно и то же поле присваивается в разных ветках условия — это один перенос, порог он не
  набирает.

## Что проверяет инструмент

Проверка: `qg:BSL-FIELD-TRANSFER` (`tools/bsl-lint.mjs`), 🟡 — в одном методе три и больше
присваивания `Приемник.Поле = Источник.Поле` или `Приемник.Вставить("Поле", Источник.Поле)`
из одного источника в один приёмник, каждое поле приёмника считается один раз. Текст находки
различает одноимённый перенос (совет — `ЗаполнитьЗначенияСвойств` или передача источника как
есть) и разноимённый (совет — переименовать поле у источника).

**Проверяются только методы из правки** — написанные или изменённые относительно версии файла
в HEAD. Перенос поштучно — обычный стиль типового кода: на корпусе УТ 11.5 и четырнадцати
расширений он есть примерно в каждом шестом модуле (2 337 модулей из 13 459). Проверка модуля
целиком выдавала бы находки по методам, которых правка не касалась. Файл без истории в git
проверяется целиком.

**Чего не ловит.** Тип приёмника и источника не выводится: перенос в структуру и перенос в
реквизиты объекта для инструмента одинаковы, решение о том, нужна ли вторая форма данных,
остаётся за читателем. Пояснение об исключении другими словами, без слова «словарь»,
инструмент не опознаёт.
