# Сначала индекс кода: правило для субагентов, читающих код

Источник блока, который дословно стоит в каждом субагенте, выходящем за пределы переданных
ему файлов (`bsl-scout`, `bsl-verifier`, `cold-reader`). Блок правится здесь и переносится в
агентов; совпадение проверяет `tests/run-tests.mjs`. Субагент читает свой файл, а не этот:
отдельный ход на загрузку правила стоил бы дороже самого правила.

## Сначала индекс кода

Индекс кода 1С — MCP-сервер навигации (например, `code-index`): определение метода,
вызывающие, состав метаданных одним вызовом вместо перебора файлов. **До первого `Read`,
`Grep` или `Glob` по коду проверь его наличие дважды:**

1. `ToolSearch` с запросом по имени: `code-index`. В OpenCode вместо этого просмотри список
   доступных инструментов — серверы MCP видны там по имени.
2. Пусто — второй запрос по смыслу: `bsl index symbol callers`. Одна неудачная попытка
   отсутствия не доказывает: имя сервера у проекта может быть своим.

**Индекс найден** — поиск по коду идёт только через него. `Grep` и `Glob` по коду запрещены.
`Read` остаётся в двух случаях: файлы, переданные тебе на входе, и точечное чтение по
строкам, которые вернул индекс. Исключение — каталоги, которых индекс не покрывает (исходники
внешних обработок и отчётов): назови их в ответе.

**Индекс найден, но не отвечает** — ошибка, таймаут, статус `indexing`. Повтори вызов один
раз. Снова нет ответа — считай индекс недоступным и действуй по следующему абзацу, назвав в
первой строке, что именно он ответил. Другие его инструменты не перебирай и не жди: зависший
сервер от повторов не оживает, а каждый повтор стоит хода.

**Индекс не найден после двух проверок** — первой строкой ответа напиши: «индекс кода
недоступен, искал: <оба запроса>; поиск перебором, полнота не гарантирована». Только после
этого работай `Grep`, `Glob` и `Read`. Молчаливый переход на перебор — дефект ответа.

## Почему дважды и почему жёстко

**Перебор дорог и неполон.** Вопрос «кто вызывает метод» через индекс — один вызов с
ответом в сотни байт. Через `Grep` и `Read` — десятки ходов и мегабайты результатов в
контексте субагента, при этом перехватчики в расширениях и вызовы через границу расширения
перебор находит хуже индекса.

**Мягкая формулировка не работала.** Прежний текст агентов называл индекс «основным
инструментом», а `Grep` — «запасным вариантом». Замер на живых прогонах показал: плагинный
разведчик ни разу не дошёл до индекса и работал перебором, не сказав об этом. Причин было
две, и обе закрыты вместе с этим правилом:

- агент был задан закрытым списком `tools`, а закрытый список в Claude Code не наследует MCP
  вовсе — `ToolSearch` в таком списке находить нечего. Поэтому читающие код агенты заданы
  списком запретов `disallowedTools`;
- правило не требовало ни проверки, ни отчёта о её исходе, и отсутствие индекса было
  неотличимо от нежелания его искать.

**Две проверки, а не одна.** Имя сервера плагину неизвестно: индекс ставит пользователь, и
называться он может как угодно. Запрос по одному имени даёт ложное «нет» на проекте с другим
именем; запрос по смыслу ловит такой случай.

**Потолок повторов.** Замер на перестраивающемся индексе: без потолка агент сделал тринадцать
безответных вызовов и ждал таймаута в пять минут — прогон вышел втрое дороже штатного. Один
повтор отличает случайный сбой от зависшего сервера; дальше повторы только стоят денег.

**Отчёт о недоступности — первой строкой.** Принцип плагина: пропуск проверки обязан оставлять
след. Факты, собранные перебором, контур обязан принять с поправкой на неполноту, а для этого
он должен о ней знать.
