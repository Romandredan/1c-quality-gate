# 1c-quality-gate в OpenCode

Плагин работает в двух харнессах: Claude Code (хуки `hooks/gate-arm.mjs` +
`hooks/gate-check.mjs`) и OpenCode (плагин `opencode/plugin/quality-gate.js`). Механика
гейта одна и та же — общее ядро `hooks/gate-core.mjs`, общие инструменты `tools/`, общий
skill `skills/quality-gate`. Различаются способ взвода, поведение при завершении сессии и
каталог состояния.

## Установка

Одна строка в `opencode.json` проекта (или в `~/.config/opencode/opencode.json`).

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["1c-quality-gate@git+https://github.com/Romandredan/1c-quality-gate.git#v3.20.0"]
}
```

Эта строка подходит обеим версиям OpenCode. Разбор конфигурации OpenCode 2.x учитывает ключ
`plugin` наравне с собственным `plugins` (`packages/core/src/config/normalize.ts` в
исходниках OpenCode), поэтому отдельной записи для 2.x не нужно. Писать `plugins` в общую
конфигурацию не стоит: OpenCode 1.x этот ключ игнорирует без сообщения об ошибке (проверено на 1.18.28:
конфигурация загружается, список плагинов пуст), и плагин не подключается. Проверено живой установкой на 2.0.30: строка с ключом `plugin` и git-ссылкой установила
пакет и зарегистрировала субагентов (первый запуск ждёт установки пакета, около 40 секунд).

Теги, выпущенные до появления поддержки 2.x, кода для неё не содержат: в 2.x закрепляйте
тег, выпущенный после неё.

**Две версии — один плагин.** Точка входа `opencode/plugin/quality-gate.js` экспортирует
оба интерфейса: V2 читает `id` и `setup(ctx)` (загрузчик 2.x отвергает модуль, у которого
по умолчанию экспортирована функция), V1 вызывает `server`. Загрузка в 1.x проверена живой
пробой на 1.18.28: хук `config` отрабатывает, субагенты, команды и MCP регистрируются.
Механика гейта общая; различается только способ регистрации состава и подписки на события
(см. таблицу ниже и раздел «Почему гейт в OpenCode мягкий»).

Перезапустите OpenCode — пакет установится сам и попадёт в кэш
`~/.cache/opencode/packages/`. Проверка: `/gate-status` отвечает «Гейт не взведён».

**Тег закрепляйте.** Без `#v3.0.0` установка тянет текущее состояние ветки `main`, а не
выпущенную версию, и два харнесса разъезжаются: Claude Code ставится по тому же тегу через
`marketplace.json`. Обновление — смена тега в этой строке и перезапуск. Если новая версия
не подхватилась, очистите кэш пакета: Bun кэширует установленное по спецификации.

Копировать в проект нечего: состав объявляется самим плагином в живой конфигурации
(хук `config`), а инструменты находит агент по переменной `QG_ROOT` (хук `shell.env`).

| Что регистрируется | V1 (OpenCode 1.x) | V2 (OpenCode 2.x) |
|---|---|---|
| навыки контуров и `shared/` | `config.skills.paths` — каталог `skills/` внутри пакета | `ctx.skill.transform` — `editor.add` с абсолютным путём к SKILL.md |
| команды `/gate`, `/gate-status` | `config.command`, тело файла становится `template` | `ctx.command.transform` — `execute` отправляет шаблон в сессию, `$ARGUMENTS` подставляется из `prompt.text` |
| субагенты — все файлы каталога `agents/` | `config.agent` из общего каталога `agents/`, тело файла становится `prompt` | `ctx.agent.transform` — `editor.update`; права инструментов переносятся в правила `permissions` (last-match-wins: база `allow *` первой, отказы после неё). Действие правила в 2.x равно имени инструмента: `shell`, `subagent`, `skill`; `write`, `edit` и `patch` делят одно действие `edit`, и оно закрыто только тогда, когда у агента закрыты и `Write`, и `Edit` |
| MCP-сервер стандартов `v8std` | `config.mcp` | `ctx.mcp.transform` (`editor.set`) |
| окружение оболочки (`QG_ROOT`, `QG_PROJECT_DIR`, `QG_STATE_DIR`, в 2.x ещё `QG_SUBAGENT_TOOL`) | хук `shell.env` | `ctx.shell.hook('create.before')` — заданное пользователем не перекрывается |

Своё имя всегда сильнее: запись пользователя с тем же именем плагин не перекрывает.

**Единственный ручной шаг** — рабочее состояние сессий не коммитить. Добавьте в
`.gitignore` проекта:

```gitignore
.opencode/.state/
.qg-analyzer/
```

**Статический анализатор.** Ставится сам при первом прогоне и живёт в каталоге, общем для
обоих харнессов: по умолчанию `~/.claude/plugins/data/1c-quality-gate-1c-quality-gate/`.
Имя историческое, каталог общий намеренно — бинарник закреплён по версии и SHA-256, для
Claude Code и OpenCode он побайтово один, а своя копия на харнесс стоила бы вторых
шестидесяти мегабайт. Если каталог с чужим именем на диске не нужен, задайте `QG_DATA_DIR` —
она перекрывает путь целиком. Разбор — [INSTALL.md](INSTALL.md).

## Отличия от Claude Code

| Аспект | Claude Code | OpenCode |
|---|---|---|
| Взвод гейта | хук PostToolUse (matcher Write/Edit/…) | `tool.execute.before/after` (write/edit/multiedit/patch/notebookedit); в 2.x — `ctx.tool.hook('execute.before'/'execute.after')`, файлы `patch` берутся из текста патча |
| Взвод по команде оболочки | хуки `gate-shell.mjs` на `Bash` и `PowerShell`: до команды, после и после упавшей | `tool.execute.before/after` на `bash` (в 2.x инструмент называется `shell`); ядро общее — `hooks/shell-core.mjs`; в 2.x снимок сверяется и после упавшей команды, а команды с `background: true` не отслеживаются |
| Подсказка о взводе | `additionalContext` хука | дописывается в результат инструмента (в 2.x подменяется `event.result`: поля результата только для чтения) |
| Контроль завершения | Stop-хук отказывает в завершении (exit 2) — **жёсткий гейт** | `session.idle`: плагин отправляет агенту сообщение и возвращает его к работе — **мягкий гейт** |
| Состояние | `.claude/.state/` | `.opencode/.state/` (через `QG_STATE_DIR`) |
| Архив принятых отчётов | `.claude/.state/qg-reports/` | `.opencode/.state/qg-reports/` |
| Корень проекта | `CLAUDE_PROJECT_DIR` | `QG_PROJECT_DIR` из хука `shell.env`; корень берётся по `worktree` (1.x) и `location.project.directory` (2.x), а не по каталогу запуска |
| Путь к инструментам | разрешается перебором в навыке | `QG_ROOT` из хука `shell.env` |
| Снятие гейта | `node "$QG/tools/gate.mjs" release …` | то же самое, без изменений |
| Итог после снятия | `systemMessage` Stop-хука, один раз | сообщение плагина на `session.idle`, один раз |
| Сброс счёта проходов цикла | хук `UserPromptSubmit` | нет — потолок в три прохода действует без сброса, четвёртый только с `--decision` |
| Модель субагента | поле `model` файла агента | не переносится — субагент идёт на модели сессии |
| Инструменты MCP у субагента | только при списке запретов `disallowedTools`; закрытый `tools` их отрезает | разрешены всегда |

### Исполнитель гейта и вложенные субагенты

Проверку проводит субагент `gate-runner` в свежем контексте: основная сессия передаёт ему
описание работы и получает вердикт, а десятки ходов прогона не оплачивают контекст длинной
сессии. Сам он запускает субагентов контуров, то есть работает на втором уровне вложенности, и
OpenCode по умолчанию этого не позволяет. Проверено живой пробой на 1.18.28:

| Условие | Без него |
|---|---|
| у субагента включён инструмент `task` и дано разрешение `permission.task` | инструмента запуска у субагента нет вовсе |
| `subagent_depth` в конфигурации не меньше 2 | отказ «Subagent depth limit reached (1)» |

**OpenCode 2.x.** Инструмент запуска субагентов называется `subagent`, а предел глубины задаётся
ключом `experimental.subagent_depth` (по умолчанию 1; сообщение об отказе называет этот ключ,
исходник — `packages/core/src/tool/plugin/subagent.ts`). Прежний ключ верхнего уровня
`subagent_depth` разбор конфигурации 2.x помечает как неподдерживаемый, а у плагина 2.x нет
доступа к конфигурации, поэтому поднять предел сам он не может. **Нужен один ручной шаг** —
в `opencode.json`:

```json
{ "experimental": { "subagent_depth": 2 } }
```

OpenCode 1.x этот ключ тоже игнорирует (проверено на 1.18.28), поэтому он безопасен в общей
конфигурации обеих версий. Без него `gate-runner` не запустит субагентов контуров и вернёт
отказ «Subagent depth limit reached (1)». Разрешение на запуск (`subagent`) плагин по-прежнему даёт только исполнителю
гейта. Права на запись в 2.x у исполнителя гейта общие для `Write` и `Edit`, поэтому запрет
править файлы проекта держится на тексте задания, а не на правах.

**OpenCode 1.x.** Оба условия плагин выставляет сам из хука `config`: `task` открыт только исполнителю гейта,
читающим субагентам он закрыт; `subagent_depth` поднимается до 2, более глубокая настройка
пользователя не понижается. Ручного шага нет. Если вложенный запуск всё же недоступен (другая
версия OpenCode, запрет в своей конфигурации), сообщение плагина называет запасной путь:
основная сессия прогоняет навык `quality-gate` сама.

### Модель холодного читателя задаётся вручную

Имя модели в OpenCode идёт с префиксом провайдера, поэтому `model: opus` из файла агента
перевести нечем, и поле отбрасывается. Для дешёвых субагентов это безвредно. Для
`cold-reader` — нет: он выносит суждение о логике, ошибка которого по форме ответа не видна, и
на слабой модели сессии читатель окажется таким же слабым. Если сессия идёт не на старшей
модели, задайте модель агента в своей конфигурации OpenCode — своя запись сильнее записи
плагина:

```json
{ "agent": { "cold-reader": { "model": "<провайдер>/<старшая модель>" } } }
```

## Почему гейт в OpenCode мягкий

У OpenCode нет механизма, которым плагин мог бы запретить завершение сессии. Вместо
блокировки плагин ловит событие `session.idle` (в V2 — durable-событие
`session.execution.succeeded` из `ctx.event.subscribe`; устаревшее `session.idle` принимается
тоже) и отправляет агенту новое сообщение со списком непроверенных правок — агент продолжает
работу и прогоняет проверку. Если один конец прогона пришёл обоими событиями, возврат один:
повтор в течение двух секунд без нового `session.execution.started` отбрасывается. Итог
после снятия гейта уходит уведомлением без хода модели: `noReply` в 1.x и `resume: false` в
2.x (для 2.x это следует из схемы API и покрыто тестом; живым прогоном не наблюдалось). Если поток событий 2.x оборвётся, плагин пишет предупреждение в стандартный поток
ошибок: возврат на паузе тогда отключён до перезапуска, взвод по правкам продолжает работать.
Прерванный прогон (`session.execution.interrupted`, `failed`) возврата не даёт: это
пользователь сам остановил работу, а не агент собрался завершать. Пользователь всегда может
прервать сессию вручную: гейт настойчив, но не запирает.

Чтобы цикл «idle → возврат» не превращался в бесконечный спам, на неизменный состав правок
даётся не более трёх автоматических возвратов (`MAX_REPROMPTS` в
`opencode/plugin/quality-gate.js`). Счётчик ведётся по сессии, любая новая правка меняет
отпечаток состава и сбрасывает его: пока работа идёт, возвраты продолжаются. Исчерпание
лимита фиксируется записью `gate-surrendered` в журнале прогонов
(`.opencode/.state/qg-runs.jsonl`) — отказ от проверки остаётся наблюдаемым фактом,
а не тихим умолчанием. Запись намеренно без поля `scope`, поэтому валидатор охвата
не засчитывает её как прогон.

Требования к снятию гейта не смягчаются: `gate.mjs release` по-прежнему требует
машиночитаемый след прогона, валидатор следа общий для обоих харнессов.
