## Триггер

`Для Каждого … Из Переменная Цикл`, где `Переменная` держит результат `Выбрать()` —
выборку результата запроса, обходчик итогов, выборку динамического списка.

## Почему

Выборка запроса — курсор, а не коллекция: у неё нет итератора, и обход падает в рантайме
«Итератор для значения не определен». Ошибку не видит ни сборка, ни статический анализатор:
выражение синтаксически безупречно, а тип берётся из выполнения. Код доходит до боевого
контура и падает на первом же вызове ветки, которую прогон не покрывал.

## Как чинить

Перебирать выборку методом `Следующий()`. Нужен именно обход коллекции — сначала
`Выгрузить()`, и уже по таблице `Для Каждого`.

#### Неправильно

```bsl
Выборка = Запрос.Выполнить().Выбрать();
Для Каждого Строка Из Выборка Цикл
	Сумма = Сумма + Строка.Сумма;
КонецЦикла;
```

#### Правильно

```bsl
Выборка = Запрос.Выполнить().Выбрать();
Пока Выборка.Следующий() Цикл
	Сумма = Сумма + Выборка.Сумма;
КонецЦикла;
```

## Когда это не дефект

- переменная переприсвоена между выборкой и циклом и к моменту цикла держит массив,
  структуру или таблицу значений;
- цикл обходит `Выгрузить()`, а не саму выборку;
- одно имя живёт в двух ветках: в одной выборка, в другой коллекция, и цикл стоит в ветке
  с коллекцией.

## Что проверяет инструмент

`qg:BSL-FOR-EACH-QUERY-SELECTION` в `tools/bsl-lint.mjs`: в одной процедуре ищет присваивание
с `.Выбрать(` справа, а ниже — `Для Каждого` по той же переменной. Находка предупреждающая, а
не блокирующая: последнее присваивание может быть не единственным, а имя не разрешается по
областям видимости — редкий чистый случай снимается чтением кода.
