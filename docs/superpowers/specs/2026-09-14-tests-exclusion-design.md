# Исключение тестовых модулей из гейта: дизайн

Статус: **утверждено 14 сентября 2026**, к реализации в v3.8.0.

## Задача

Гейт проверяет каждый изменённый файл 1С, включая модули автотестов. На рабочем проекте
новый тестовый модуль прошёл полный прогон класса C3: архитектура уровня 3, контур кода L2,
находки анализатора вида `MagicNumber` и `DuplicateStringLiteral`. Тестовый код не входит в
архитектуру и логику построения проекта, и его проверка — работа без пользы, которая
приучает обходить гейт.

Решение владельца: тестовые файлы исключаются **полностью**. Признак — пути в настройке
проекта; автоопределение не исключает, а только подсказывает.

## Настройка

Раздел `tests` файла `.1c-quality-gate.json`, ключ `paths` — список путей от корня проекта.

- Путь без `*` и `?` — файл или каталог целиком: `src/cfe/Автотесты` покрывает всё под ним.
- Маски: `*` — часть одного сегмента, `**` — любое число сегментов, `?` — один символ.
  Маска, совпавшая с каталогом-предком файла, покрывает файл: `**/тест_*` покрывает и
  `CommonModules/тест_М.xml`, и `CommonModules/тест_М/Ext/Module.bsl`. Уточнено по ревью:
  исходный вариант покрывал только одно из двух.
- Разделитель `/`; обратный слэш приводится к прямому; ведущий `./` и хвостовой `/`
  отбрасываются. Сравнение без учёта регистра.
- Недопустимо: пустая строка, абсолютный путь (`/…`, `C:…`), сегмент `..`, значение не
  массив строк.

Умолчание — пустой список. В создаваемый плагином файл раздел попадает пустым с описанием,
как остальные. В существующие файлы плагин ничего не дописывает (правило «конфиг заводит
инструмент, создание разовое»).

## Исключение на взводе

Единственная точка — `armGate` в `hooks/gate-core.mjs`, её вызывают PostToolUse-хук
Claude Code и плагин OpenCode. Ядро получает функцию `readConfig` снаружи — так же, как
`ensureConfig`, чтобы не тянуть конфигурацию туда, где она недоступна.

- Файл 1С по пути из `tests.paths` гейт не взводит: `armGate` возвращает `null`, хук молчит.
- Если этот файл уже лежит в сессии (взведён до появления настройки), правка убирает его
  оттуда; опустевшая сессия удаляется из состояния.
- Файл вне корня проекта не исключается никогда: пути настройки относительные.
- Ошибка чтения или неверное значение настройки на взводе дают пустой список: хук качества
  не имеет права ломать работу. Ошибку показывает план (ниже).

Всё, что идёт после взвода — Stop-хук, `gate.mjs plan`, профиль, `verify`, `release`, —
работает от списка файлов сессии и исключённых файлов не видит без отдельных правок.

Сессия, правившая только тесты, гейт не взводит и завершается без прогона и отчёта.

## След

- Строка `[qg scope: ...]` получает `config=custom:…+tests` существующим механизмом
  переопределённых разделов (`overriddenSections`). Отдельной записи следа не заводится.
- `gate.mjs plan` печатает раздел «Исключено настройкой проекта» с действующими путями и
  кладёт их в JSON-вывод (`excludedPaths`).

## Подсказка YAxUnit

`gate.mjs plan` читает взведённые `.bsl` и ищет экспортную процедуру `ИсполняемыеСценарии`
(признак тестового модуля YAxUnit). Найденные печатаются разделом «Похоже на тесты YAxUnit»
с советом добавить путь в `tests.paths`; в JSON — `yaxunitHint`. Сама подсказка ничего не
исключает: эвристика не решает за проект.

## Неверная настройка

`gate.mjs plan` проверяет `tests.paths` до расчёта профиля. Неверное значение — отказ с кодом
2 и объяснением, тем же путём, что неверные `archetypes.custom`: молча применённая частично
неверная настройка хуже отказа.

## Сопоставление путей

Отдельный модуль `tools/path-match.mjs`: `normalizePattern`, `validatePatterns`,
`matchesAny(rel, patterns)`. Используется ядром гейта и планом.

## Тесты

- `tests/gate-core.test.mjs`: взвод файла по исключённому пути не пишет его в сессию;
  соседний файл взводится; ранее взведённый файл снимается правкой; опустевшая сессия
  удаляется; файл вне корня не исключается; падающий `readConfig` не ломает взвод.
- `tests/run-tests.mjs`: сопоставление путей (каталог, маски, регистр, кириллица, обратный
  слэш), отказ на недопустимых путях; раздел `tests` в шаблоне и в `DEFAULTS`; поле
  `config=custom:tests`; план печатает исключения и подсказку YAxUnit; план отказывает на
  неверной настройке.

## Документация

`docs/CONFIG.md` — раздел `tests`. Выпуск — MINOR (новый необязательный ключ в прежнем
контракте), v3.8.0.

## Что не делается

- Автоматическое исключение по признаку YAxUnit.
- Частичное исключение (гигиена и XML для тестов).
- Фильтрация уже взведённых тестовых файлов в плане и снятии гейта без их новой правки.
