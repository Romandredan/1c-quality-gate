## Триггер

`ЗначенияРеквизитовОбъекта` по ссылке, которую только что вернул запрос этого же модуля.

## Почему

Запрос находит объект, и сразу за ним помощник библиотеки читает реквизиты этого объекта:
два обращения к базе там, где хватило бы одного. Сбор данных при этом размазан по двум
местам: что читается из базы, видно только обходом вызовов, а поле, добавленное в одно место,
легко забыть в другом.

## Как чинить

#### Неправильно

```bsl
Функция НастройкиПоСкладу(Склад)
    Записи = УчетныеЗаписиСклада(Склад);      // запрос возвращает колонку ссылок
    Реквизиты = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Записи[0], "Адрес, Логин, Таймаут");
    ...
```

#### Правильно

```bsl
Функция НастройкиПоСкладу(Склад)
    Записи = УчетныеЗаписиСклада(Склад);      // запрос выбирает и ссылку, и Адрес, Логин, Таймаут
    Настройки = Записи[0];
    ...
```

Поля, нужные дальше, выбираются в том же запросе, который находит объект, и приходят строкой
результата.

## Когда это не дефект

- объект пришёл параметром извне модуля, и запроса, который его нашёл, в модуле нет;
- читается реквизит, который запрос получить не может, — хранилище значения;
- чтение происходит не всегда, а только в редкой ветке, и выбирать поле для каждой строки
  запроса дороже, чем прочитать его однажды; это поясняется комментарием у чтения.

## Что проверяет инструмент

Проверка: `qg:BSL-QUERIED-OBJECT-ATTRIBUTES` (`tools/bsl-lint.mjs`), 🟠 — первый аргумент
`ОбщегоНазначения.ЗначенияРеквизитовОбъекта` / `ЗначениеРеквизитаОбъекта` получен из результата
запроса: в этом же методе (выборка, выгрузка, колонка, элемент по индексу, строка цикла) либо
из функции модуля, которая возвращает результат запроса. Если аргумент — параметр метода,
инструмент делает один шаг по вызовам внутри модуля и проверяет, что передают вызывающие.

**Чего не ловит.** Вызовы из других модулей не прослеживаются. Тип реквизита из текста модуля
не выводится, поэтому хранилище значения даёт ложную находку — это сказано в её тексте.
